# attendance-gen

כלי שורת פקודה ב-Python שמקבל דוח נוכחות בפורמט PDF, מזהה את סוג הדוח, ומפיק ממנו **וריאציה הגיונית ודטרמיניסטית** באותו מבנה ובאותו עיצוב.

- מזהה אוטומטית שני סוגי דוחות: `TYPE_A` (טבלה עם הפסקות ואחוזי שעות נוספות) ו-`TYPE_B` (כרטיס עובד חודשי עם מחיר לשעה).
- מחיל על כל סוג סט כללים דטרמיניסטיים: סיום אחרי התחלה, שעות יומיות וחודשיות בטווח סביר, סכומים עקביים.
- מפיק PDF חדש עם אותם כותרות, סדר עמודות, שורות וסכומים.
- אותו קובץ קלט נותן תמיד אותו דוח.

הדוח שנוצר מסומן כדוגמה (סימן מים "דוגמה" וסיומת בכותרת). זו החלטה מכוונת.

## דרישות

- Python 3.12 ומעלה (הפרויקט נבדק על Python 3.14), כך שהפקודה `python` זמינה ב-`PATH`.
- **Tesseract OCR** עם חבילות השפה **עברית (`heb`)** ואנגלית (`eng`). הקוד מריץ OCR בשפות `heb+eng`, ולכן בלי חבילת העברית ההרצה נכשלת.
- פונט `.ttf` עם תמיכה בעברית. הכלי מחפש לפי הסדר: הדגל `--font`, משתנה הסביבה `ATTENDANCE_FONT`, ואז Arial (Windows, macOS) או DejaVu Sans (Linux: `sudo apt install fonts-dejavu-core`).

### התקנת Tesseract

- **Windows:** מתקינים את Tesseract (למשל מההתקנה של UB Mannheim), ובמהלך ההתקנה מסמנים את נתוני השפה **Hebrew**. מוסיפים את תיקיית ההתקנה (ברירת מחדל: `C:\Program Files\Tesseract-OCR`) ל-`PATH`.
- **Ubuntu/Debian:** `sudo apt install tesseract-ocr tesseract-ocr-heb`
- **macOS:** `brew install tesseract tesseract-lang`

בדיקה: `tesseract --list-langs` צריך להציג `heb` ו-`eng`.

## הרצה

```powershell
python -m attendance_gen data\samples\n_r_5_n.pdf -o data\output
```

הפלט נכתב ל-`<שם הקובץ>_sample.pdf` בתיקיית הפלט (ברירת מחדל: `data/output`).

```
נוצר: C:\Reports\data\output\n_r_5_n_sample.pdf
סוג דוח: TYPE_B, שורות: 24, אזהרות קריאה: 1
```

### אפשרויות

| דגל | משמעות |
|---|---|
| `-o`, `--output-dir` | תיקיית הפלט (נוצרת אם חסרה) |
| `--overwrite` | מותר לדרוס קובץ קיים. בלי הדגל, קובץ קיים גורם לשגיאה |
| `--font` | נתיב לקובץ פונט `.ttf` עם תמיכה בעברית. בלעדיו נבדק `ATTENDANCE_FONT`, ואז פונטים מוכרים של המערכת |
| `--company`, `--employee` | שם החברה ושם העובד שמופיעים בדוח (ברירת מחדל: "חברה לדוגמה", "עובד לדוגמה") |
| `--period YYYY-MM` | חודש הדוח, כגיבוי כשלא ניתן לקרוא אותו מהקובץ. משפיע רק על `TYPE_B` |
| `-v`, `--verbose` | מדפיס גם את כל אזהרות הקריאה ואת הלוג |

קוד היציאה הוא 0 בהצלחה, ו-2 לשגיאה צפויה (הודעה בעברית מודפסת ל-stderr).

### אזהרות קריאה

הדוח המקורי נקרא ב-OCR, ולכן חלק מהשורות עלולות להיקרא שגוי. הכלי **לא מנחש**: שורה לא אמינה נזרקת ומתועדת באזהרה, ואפשר לראות אותן עם `-v`.

| קוד | משמעות |
|---|---|
| `ROW_UNREADABLE` | לא כל תאי השורה נקראו. השורה נשארת יום עבודה, אבל לא משמשת כמקור לשעות |
| `ROW_INCONSISTENT` | כניסה, יציאה וסה"כ לא מתאימים זה לזה |
| `ROW_IGNORED` | נקרא תא בודד בשורה: רעש של OCR, לא יום עבודה |
| `ROW_OUTLIER` | משמרת רחוקה מדי מהמשמרת האופיינית |
| `TOTAL_NOT_CONFIRMED` | (`TYPE_A`) הסכום המחושב לא נקרא ב-OCR, והקוד סומך על החישוב |
| `PERIOD_MISMATCH`, `PERIOD_OVERRIDDEN` | החודש בכותרת שונה מהחודש בתאריכים, או שהוחלף ידנית ב-`--period` |
| `RATE_NOT_FOUND`, `RATE_AMBIGUOUS` | (`TYPE_B`) מחיר לשעה לא זוהה, או שיש כמה מועמדים |

אם נקראו פחות ממחצית השורות, ההרצה נכשלת עם `ParseError` במקום להפיק דוח חלקי.

## הזרימה

```
PDF ─► בדיקת קלט ─► OCR ─► זיהוי סוג ─► פירוק ─► וריאציה ─► אימות ─► יצירת PDF
```

1. **בדיקת קלט ויעד** לפני ה-OCR היקר (כשלון מהיר).
2. **OCR** לעמוד (`pymupdf` להמרה לתמונה, `pytesseract` לקריאה). הטקסט משמש לזיהוי הסוג ולקריאת החודש.
3. **זיהוי סוג:** לכל פרסר יש ציון התאמה. נדרש ציון מינימלי (0.3) ומרווח מהמקום השני (0.2), אחרת `UnknownReportTypeError`.
4. **פירוק:** `TYPE_B` נקרא תא אחרי תא מרשת הטבלה (OpenCV), `TYPE_A` מהטקסט. התוצאה היא `ParseResult` עם המשמרות שנקראו ועם רשימת האזהרות.
5. **וריאציה:** אסטרטגיה לכל סוג דוח, עם `seed` שנגזר מ-SHA-256 של תוכן הקובץ.
6. **אימות:** הדוח החדש נבדק מול הכללים. דוח שלא עובר לא מוחזר, ונזרקת `GenerationError`.
7. **יצירה:** כתיבה לקובץ זמני (`.part`) והחלפה אטומית, כך שלא נשאר פלט חלקי אם משהו נכשל.

## כללי הווריאציה

כל סוג דוח מגדיר אובייקט `GenerationRules` (נתונים, לא קוד): ימי שבוע מותרים, טווח שעות מותר, גודל הסטייה בשעות (`TYPE_B`: עד 15 דקות בקפיצות של 5), מקסימום שעות נטו ביום (`TYPE_B`: 4), מקסימום שעות בחודש (`TYPE_B`: 120) והפסקה מקסימלית.

האימות בודק, בין השאר:

- יציאה אחרי כניסה, וסה"כ שעות תואם לכניסה, ליציאה ולהפסקה (סבילות של 0.02).
- יום עבודה חוקי, שעות בטווח, ומקסימום שעות יומי וחודשי.
- אין תאריכים כפולים, והתאריכים בסדר כרונולוגי.
- `TYPE_B`: מחיר לשעה חייב להיות חיובי, ואין הפסקה.

**ימי עבודה ב-`TYPE_B`:** ימי העבודה בדוח החדש הם הימים שהיו עם נתונים בכרטיס המקורי, וימים ריקים (שבתות, חגים, ימי חופש) נשארים ריקים. כך אין צורך בלוח חגים. הווריאציה היא בשעות הכניסה והיציאה. ההנחה: שורה N בטבלה היא היום ה-N בחודש.

## מבנה הפרויקט

```
src/attendance_gen/
  __main__.py            ממשק שורת הפקודה (פרמטרים, הדפסה, קודי יציאה)
  pipeline.py            התזמור: ה-OCR, הזיהוי, הפירוק, הווריאציה והיצירה
  formats.py             רישום סוגי הדוחות (פרסר + אסטרטגיה + פריסה)
  domain/                המודל (AttendanceRow, AttendanceReport) והאימות
  parsing/               OCR, זיהוי סוג, רשת הטבלה, תאים, פרסר לכל סוג
  transformation/        כללים (rules), אסטרטגיה לכל סוג, פירוק לאחוזי שעות
  generation/            פריסות (layout) ויצירת ה-PDF
tests/
```

## החלטות תכנון

- **הפרדה בין מודל, פירוק, וריאציה ותצוגה.** `domain` לא תלוי ב-OCR או ב-PDF, ולכן אפשר לבדוק את הכללים בלי קבצים.
- **כללים כנתונים.** הבדלים בין סוגי דוחות הם אובייקטים (`GenerationRules`, `LayoutSpec`), לא תנאים בקוד. הרנדרר לא יודע אילו סוגי דוחות קיימים.
- **רישום פורמטים (`ReportFormat`).** סוג חדש הוא אובייקט אחד נוסף, בלי לשנות קוד קיים.
- **הזרקת תלויות.** `Pipeline` מקבל את הפורמטים, את הרנדרר ואת פונקציית ה-OCR מבחוץ, כך שהבדיקות רצות בלי Tesseract.
- **דטרמיניזם.** ה-`seed` נגזר מתוכן הקובץ, ולכן אותו קלט נותן אותו פלט. נבדק: הרצה מתיקייה אחרת ומסביבה וירטואלית חדשה נתנה דוח עם תוכן זהה.
- **להיכשל בקול רם ולא לנחש.** שורת OCR לא אמינה נזרקת עם אזהרה. קריאה חלשה מדי או דוח שלא עובר אימות מפסיקים את ההרצה.
- **אי-שינוי.** שורות ודוחות הם `dataclass` קפוא. סכומים כספיים הם `Decimal` ומעוגלים לאגורה.
- **יצירה בטוחה.** כתיבה אטומית, ונתיב פלט שלא יכול לצאת מתיקיית הפלט.
- **פרטיות.** הלוג מכיל מטא-נתונים בלבד (שמות קבצים, מספר שורות), לעולם לא טקסט מהדוח.

## הנחות ומגבלות מוכרות

- **עמודת ההערות ריקה בפלט.** תאי הנתונים נקראים עם רשימת ספרות בלבד, ולכן טקסט כמו "ערב ראש השנה" במקור לא משוחזר. הימים עצמם כן נשמרים ריקים.
- **הטבלה ב-`TYPE_B` נגמרת באחרון בחודש.** במקור היא נמשכת גם לשורה אחת מהחודש הבא.
- **הבדלי עיצוב קטנים:** רוחב הטבלה, כותרות מודגשות בשתי שורות, ושורה ריקה בטבלת הסיכום.
- **ספירת הימים:** הדוח מציג את מספר השורות שבהן יש משמרת. אם הכרטיס המקורי מציג בכותרת מספר שונה משורותיו, הפלט נשאר עקבי עם שורותיו.
- **`TYPE_A`: פירוק אחוזי השעות** (8 שעות רגילות, שעתיים ב-125%, השאר ב-150%, שבת כולה בעמודת "שבת") הוא **הנחה** שרשומה בקוד. בכרטיסים שבדקתי כל השעות ב-100%, ולכן אין לי כרטיס עם שעות נוספות לאימות.
- **חגים לא מוכרים למחולל.** ב-`TYPE_B` הם נשמרים כי הימים הריקים נלקחים מהמקור.
- **תלות ב-Tesseract ובפונט עברי** במחשב שמריץ.

## הוספת סוג דוח חדש

1. מוסיפים ערך ל-`ReportType` (`domain/models.py`).
2. כותבים פרסר שיורש מ-`BaseParser`: `score` (ציון התאמה) ו-`parse` (או `parse_document` אם צריך את קובץ ה-PDF עצמו).
3. כותבים אסטרטגיה שיורשת מ-`BaseTransformationStrategy` עם `GenerationRules` משלה.
4. מגדירים `LayoutSpec` ב-`generation/layouts.py`.
5. מוסיפים `ReportFormat(...)` ל-`DEFAULT_FORMATS` ב-`formats.py`.

## פתרון בעיות

| הודעה | מה לעשות |
|---|---|
| Tesseract OCR is not installed or not on PATH | להתקין Tesseract ולהוסיף ל-`PATH` (ראו "דרישות") |
| OCR failed ... | לבדוק ש-`tesseract --list-langs` מציג `heb` |
| no Hebrew-capable font found | להעביר `--font נתיב\לקובץ.ttf`, או להגדיר את משתנה הסביבה `ATTENDANCE_FONT` |
| ambiguous report type | הקובץ לא מזוהה בביטחון כאחד משני הסוגים |
| לא נמצאו חודש ושנה בטקסט | להעביר `--period YYYY-MM` (`TYPE_B`) |
| output already exists | להוסיף `--overwrite` או לבחור תיקיית פלט אחרת |
